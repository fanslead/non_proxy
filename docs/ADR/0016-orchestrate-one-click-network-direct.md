# ADR-0016：桌面端编排一键网络直连且不虚报生效

- 状态：已接受
- 日期：2026-07-31

## 背景

ADR-0014 和 ADR-0015 已建立网络配置档、签名快照和 macOS 运行时网络识别，但普通用户
仍不应理解指纹类型、配置档 ID、revision 或 Provider ACK。桌面端需要把“检测当前网络”
和“让此网络直连”组合成一个可恢复流程，同时不能把多个控制面写操作伪装成原子事务，
也不能在 Provider 尚未确认时声称流量已经直连。

## 决策

1. 共享 Avalonia 页面只依赖 `ICurrentNetworkEnvironment`、`INetworkProfileService` 和
   `IPolicyService`。平台宿主负责采集；网络档案 RPC、策略 RPC 和状态解释留在共享层，
   Windows 后续只需提供采集实现，不复制页面或 ViewModel。
2. 用户点击检测后，页面以指纹类型和值匹配现有档案。显示名只是可编辑标签，不参与
   身份判断；原始 SSID 不进入桌面领域 DTO。
3. 一键直连先保存网络档案，再保存引用档案 ID 的 `NETWORK + DIRECT` 策略，并复用统一
   快照发布流程。已有 active 或 pending 的相同直连规则不重复写入或制造新快照。
4. 新档案保存成功而策略写入明确拒绝时，桌面端按新档案返回的 revision 尝试删除它。
   如果策略 RPC 连接中断、结果未知，或者策略草稿已被接受但发布失败/待确认，保留档案，
   因为此时回收可能破坏已提交或即将提交的引用。
5. 页面状态来自权威目录与 `PolicyStatus`：
   - 没有策略：未创建直连规则；
   - draft：规则已保存但未发布；
   - pending：等待系统组件确认；
   - active：已应用；
   - pending removal：正在从数据面移除；
   - rejected：应用失败。
6. 删除网络配置时，先删除所有引用该档案的网络策略草稿，再按最新 revision 删除档案。
   策略发布可能仍在等待 ACK，因此删除成功文案必须保留旧快照尚未移除的边界。
7. UI 展示指纹类型、截断后的脱敏值和匹配精度。接口类型降级必须明确提示同类型网络
   可能共用配置；网关降级必须提示路由器变化后需要重新检测。

## 结果

- 普通用户不需要编写代理规则或知道网络请求地址，即可建立整个网络环境的直连策略。
- 多步写入拥有明确的失败回收边界，不会把未知结果当成失败后随意删除。
- “已保存”“等待确认”“已应用”和“实际路径证据”保持不同事实层级。
- 单元测试和 Avalonia 渲染测试可以覆盖编排与文案，但真实 SSID 授权、System Extension
  ACK 和 DIRECT 出口仍必须在正式签名设备上验收。
