# ADR-0040：订阅刷新使用凭据补偿和数据库乐观并发编排

## 状态

已接受。

## 背景

订阅 URL、节点密码位于系统凭据库，订阅源和出口元数据位于 SQLite，两者无法参加同一个事务。
如果先提交数据库再写凭据，数据面可能读到不存在的密钥；如果先写凭据但数据库提交失败，又会
留下无归属秘密。远程请求还可能在用户重配置期间返回，不能覆盖较新的源或节点状态。

## 决策

1. `gatewayd` 的 `SubscriptionService` 是创建、重配置和手动刷新的唯一编排边界。控制 RPC
   接收 URL 字节后立即放入零化内存；URL、响应正文、节点密码和凭据引用都不进入响应或日志。
2. 创建和重配置先校验源 revision、展示字段、刷新间隔及 HTTPS URL，再安全拉取完整响应。
   拉取或解析失败时不写入新 URL 凭据，也不改变已有源。
3. 节点身份使用规范化主机、端口和 Shadowsocks 加密方法的 SHA-256；显示名称、顺序和密码
   不参与身份。出口标识使用订阅 ID 哈希和节点哈希命名空间，密码轮换沿用同一出口并递增
   revision，重复身份在写入前拒绝。
4. 新 URL 与全部新节点凭据先写入系统凭据库，然后以源 revision、内容 generation、节点
   ownership 和出口 revision 为条件提交 SQLite。数据库失败时删除本次全部新凭据；提交成功
   后再清理被替换的旧凭据。事后清理失败不回滚权威数据库，而是通过稳定告警和计数返回。
5. 手动刷新先从系统凭据库读取 URL。响应 SHA-256 与当前内容哈希一致时，只调用
   `record_unchanged`；失败时在同一源 revision/generation 上记录稳定错误码，并采用 1 分钟起、
   最长 30 分钟的有界指数退避。并发重配置会让旧请求的成功或失败回写因 CAS 冲突而失效。
6. 控制面只开放安全摘要的列表、创建/更新和手动刷新 RPC。摘要包含状态、时间、错误码、
   revision、generation 和节点数，不包含 URL、主机路径、Token、节点端点或任何凭据引用。
7. Unix 与 Windows 的 `gatewayd` 生命周期启动同一个到期调度器。调度器每 30 秒扫描最多
   100 个到期源，同一源不会重复进入在途集合，最多并发刷新 4 个；每个源仍调用同一个
   `SubscriptionService`，单个失败只写回该源的错误码和退避时间。RPC 调用取消不会取消已经
   启动的原子刷新；关机先关闭共享任务入口，再排空调度任务及已脱离调用方的刷新任务。

## 后果

- 系统凭据库与 SQLite 仍不是分布式事务，但每个失败窗口都有明确补偿和用户可见的残留计数。
- 相同节点改名、换序或换密码不会产生新身份；主机、端口或加密方法变化会产生新节点并让旧
  节点进入缺失状态。
- 当前远程格式只接受已支持的 Shadowsocks Base64 订阅；VMess、Trojan、WireGuard、
  OpenVPN 和供应商私有格式不会被误识别为可用。
- 删除语义和桌面管理页仍需在这一编排边界上实现，不能绕过服务直接写库。

## 验收边界

单元与集成测试覆盖首次创建、密码轮换的稳定身份、旧凭据清理、内容未变化、失败状态退避、
URL 重配置失败回滚、四路并发限制、调用取消继续提交以及关机任务排空；契约检查覆盖 C#/Swift
生成物。本证据不代表真实公网订阅、系统 Keychain/Credential Manager 授权、系统重启后的
真实定时行为或桌面交互已经验收。
