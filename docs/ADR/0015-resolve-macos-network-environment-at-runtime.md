# ADR-0015：macOS Provider 在判定时解析当前网络环境

- 状态：已接受
- 日期：2026-07-31

## 背景

ADR-0014 已让签名策略快照携带脱敏网络配置档目录，但仅有目录不能让网络规则生效。
DNS Provider 原有的 `dns-...` 值是进程内缓存分区，透明代理没有传入任何网络配置档
ID。若两个 Provider 分别实现识别或在快照外先解析 ID，网络切换和策略热更新时可能
得到不一致结果。

macOS 还存在明确的平台限制：当前 SSID 通过 CoreWLAN 获取，并受定位服务与用户授权
约束；后台组件不能假设始终能读取。VPN 存在时，全局默认路由通常指向 `utun`，不能
把该虚拟网关误认为物理网络身份。

## 决策

1. DNS 与透明代理共用 `MacNetworkEnvironmentMonitor`。它使用 `NWPathMonitor` 观察路径，
   优先选择当前实际使用的 Ethernet、Wi-Fi 或 Cellular 物理接口，并保留物理接口供
   DIRECT socket 显式绑定。
2. Wi-Fi SSID 使用 CoreWLAN 的原始 `ssidData`，在回调栈内立即计算 SHA-256；原始值不
   写入状态、日志、RPC、诊断包或策略快照。读取失败时不阻止 Provider 启动。
3. 默认网关从 SystemConfiguration 的 per-service IPv4/IPv6 动态状态读取，只接受与
   已选物理接口名相同的服务。规范化身份为地址族、规范化 IP 和可用时的链路层地址，
   再计算 SHA-256；链路层地址用于区分大量都使用 `192.168.1.1` 的不同局域网。不得
   使用可能指向 VPN `utun` 的全局默认路由。
4. 同时观测到多个指纹时，固定按 Wi-Fi SSID、默认网关、接口类型的顺序解析。精确
   指纹优先于粗粒度回退；同类指纹再按值排序以保证确定性。
5. `ProviderPolicyRuntime.evaluate` 在一次不可变快照读取中完成指纹映射、上下文构造和
   策略判定。热更新不能产生“旧目录 ID + 新策略”的混合结果。
6. 每条新流量只读取一次网络环境快照。策略解析、DNS 缓存分区与 DIRECT 物理接口均
   来自这次读取；即使其间切换网络，代理失败后的直连回退也不能改用新网络接口并沿用
   旧网络的决策。旧接口失效时让连接失败，由下一条流量按新快照重新判定。
7. DNS resolver 请求继续使用随路径、接口和上游变化的 `dns-...` 缓存分区；策略观测
   与判定上下文使用稳定网络配置档 ID。两者不得互换。
8. 两个 System Extension 都声明沙箱定位能力。正式签名 provisioning profile 必须
   包含对应权限。macOS 设备验收必须分别覆盖“已授权可读 SSID”和“拒绝授权后按网关/
   接口类型降级”两种场景；本地构建通过不代表用户已授予定位权限。

## 结果

- DNS 与透明流量在同一网络、同一快照下得到相同的配置档身份。
- VPN 全局路由不会污染物理网络指纹，用户切换网络后新流量会自动采用新策略。
- SSID 不可用不会中断网络，默认网关通常仍可区分家庭、公司等网络，接口类型作为
  最后的低精度回退。
- 原始网络身份只在采集栈帧中短暂存在，控制面和诊断面继续只处理脱敏值。
