# ADR-0032：从活动证据创建签名约束的应用直连规则

- 状态：Accepted
- 日期：2026-08-01

## 背景

产品方案要求用户能在最近连接中点击“让这个应用始终直连”。活动页原先只展示应用名称、
目标、决策和路径，控制 RPC 也没有返回 Provider 已识别的签名、父应用与 Helper 关系。如果仅用
显示名或单个 Helper 的进程身份创建规则，同名程序可能被误匹配，应用升级后的辅助进程也可能
遗漏。历史记录在迁移前没有签名证据，不能事后猜测补齐。

快捷入口同时是一项策略写操作。按钮点击不能跳过确认，也不能把“草稿已保存”表述成数据面
已经切换；真实生效仍取决于编译、快照发布与必需 Provider ACK。

## 决策

1. V12 以追加列保存连接决策中的 `app_signer_id`、`app_parent_stable_id` 和
   `app_helper_group_id`。写入来源只能是通过 Provider 会话认证并完成领域校验的
   `AppIdentity`；旧行保持空值，不执行推断或回填。
2. `ConnectionDecisionSummary` 只追加字段 25～27。Rust、C# 和 Swift 契约继续由仓库生成器
   生成，v1 服务与现有字段保持兼容。
3. 桌面活动页同时读取最近决策和策略目录。只有记录属于当前平台、不是系统保护规则、稳定
   身份不是 `unknown-app`、签名身份存在，且相同父/主应用稳定身份没有任何应用或应用加目标
   作用域规则时，才允许准备快捷规则。禁用项显示“系统保护流量”“其他平台记录”“应用身份不足”或
   “已有应用规则”。
4. Helper 有父应用身份时以父身份作为 `AppMatcher.stable_id`，否则使用当前稳定身份；Matcher
   同时携带观测到的 signer。macOS 只有经过 Provider 认证的父/Helper 关系才设置
   `include_helpers = true`；Windows 当前设置为 false 并按精确可执行文件身份匹配。活动显示名
   只作为规则名称，不参与匹配。
5. 用户必须在确认卡中看到应用、签名身份、父/主稳定身份，以及“只影响之后的新连接”和
   “等待系统组件确认”的说明。取消不写入任何状态。
6. 确认后复用现有 `SaveAsync`/`UpsertPolicy`、编译和快照发布链路，不新增桌面直写数据库或
   绕过服务端的快捷 RPC。服务端拒绝、并发 pending 或编译失败继续使用现有稳定错误边界。
7. `Accepted=true, Applied=false` 只展示服务端 pending 消息。刷新后以权威策略目录禁用重复
   创建；只有 Provider ACK 后现有策略状态才可显示为已应用。

## 结果

- 普通用户无需知道应用请求了哪些域名，也无需手填 Bundle ID 或进程路径。
- 快捷规则继承应用选择器相同的稳定身份、签名约束和平台 Helper 语义，不会把显示名当安全
  边界。
- 迁移前记录继续可审计，但不会被升级成并不存在的身份凭据。
- 仓库测试能证明迁移、映射、资格判断和发布编排；不能替代正式签名应用、真实 Provider ACK
  与第三方 VPN 共存路径的设备验收。
