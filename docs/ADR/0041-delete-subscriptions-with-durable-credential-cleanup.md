# ADR-0041：订阅删除与凭据回收使用持久清理队列

## 状态

已接受。

## 背景

订阅地址和节点密钥位于系统凭据库，订阅源、节点归属和出口位于 SQLite。两种存储无法加入
同一事务。仅在数据库提交后立即删除旧凭据，会在进程崩溃、系统凭据库暂时不可用或关机时
留下无法再次定位的孤儿秘密。删除订阅还必须避免移除默认出口、策略或出口组仍在使用的节点。

## 决策

1. V0014 新增 `credential_cleanup_queue`，只保存最长 512 字符的凭据引用、尝试次数、下次
   尝试时间和稳定错误码，不保存 URL、Token、用户名、密码、密钥或响应内容。数据库文件仍
   使用 owner-only 权限。
2. 订阅刷新、订阅地址重配置和手动出口导入在保存新权威状态的同一个 IMMEDIATE 事务中，把
   已被替换的凭据引用加入队列。事务回滚时清理项也回滚，旧配置继续引用旧凭据。
3. `DeleteSubscriptionSource` 必须通过会话能力认证并提供非零 `expected_revision`。存储事务先
   读取全部订阅归属出口，拒绝删除当前默认出口以及被任一策略或出口组引用的出口；随后把
   URL 与节点凭据引用排队，删除源、归属和出口并写入审计事件。任一步失败都会回滚。
4. SQLite 提交后立即尝试从系统凭据库删除。不存在的凭据视为幂等成功；成功项从队列移除，
   失败项保留并采用 1 分钟起、最长 30 分钟的指数退避。每次订阅调度扫描先处理最多 100 个
   到期清理项，因此重启后仍可继续。
5. 凭据删除失败不恢复已经删除或更新的权威配置。RPC 返回稳定告警和失败数量，不返回凭据
   引用。队列更新暂时失败时保留原到期项，使后续扫描再次尝试，删除成功但队列完成写失败也
   可依靠“凭据不存在即成功”安全收敛。
6. 新凭据写入后若 SQLite CAS 失败，gateway 先把这些新引用加入同一队列再尝试删除。系统
   凭据库与 SQLite 同时不可用时无法实现跨存储绝对原子性；调用会保留明确失败和清理告警，
   不把此状态误报为成功。

## 后果

- 订阅删除不留下可路由的半成品状态，清理故障也不会把数据库恢复成已经失效的旧配置。
- 清理队列属于安全元数据而非秘密，但仍不通过控制 RPC、诊断文档或日志公开具体引用。
- 手动出口导入和远程订阅共用同一回收协议，避免形成两套不同的凭据生命周期。
- 桌面管理页仍需提供引用冲突的可理解提示和明确删除确认；本 ADR 只证明后端语义。

## 验收边界

存储测试覆盖队列迁移、旧库升级、订阅删除的原子性、默认出口引用保护、导入与旧凭据排队的
同事务提交以及 CAS 冲突回滚。gatewayd 测试覆盖系统凭据删除失败后数据库状态不复原、两项
凭据持久排队、退避到期与成功重试清空。测试不证明真实 Keychain/Credential Manager 授权、
进程被强制终止后的设备级恢复或桌面交互已经验收。
