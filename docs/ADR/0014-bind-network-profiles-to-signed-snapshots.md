# ADR-0014：网络配置档以脱敏指纹绑定不可变快照

- 状态：已接受
- 日期：2026-07-31

## 背景

策略模型已经支持 `NetworkMatcher.profile_id`，但 Provider 只收到规则中的档案标识，
并不知道该标识对应哪个真实网络。DNS Provider 先前生成的 `dns-...` 标识包含本次进程
随机值和网络变化代数，只适合隔离缓存，不能代表用户配置的“家庭”“公司”等稳定档案。
若把该临时值直接传给策略引擎，网络规则永远无法可靠命中；若把原始 SSID 放进快照，
又会扩大隐私数据的暴露面。

## 决策

1. `gatewayd` 持有网络配置档权威目录。档案由稳定 ID、用户显示名、指纹类型、脱敏
   指纹值和乐观 revision 组成；不得接收或持久化原始 SSID。
2. 首批指纹只允许 `wifi_ssid_sha256`、`default_gateway_sha256` 和受限的
   `interface_class`。同一指纹只能对应一个档案，否则 Provider 无法得到唯一身份。
3. 网络配置档使用鉴权控制 RPC 管理。目录稳定排序并带 catalog generation；删除仍被
   策略引用的档案必须失败，不能依赖 SQLite 外键错误向用户表达语义。
4. 新生成的 `CompiledPolicyPayload` 使用 format version 2，把按 ID 排序的脱敏档案
   目录随策略下发。档案 ID、指纹类型和值进入 Rust/Swift 共识内容哈希；显示名和
   revision 不参与数据面语义哈希。
5. 编译器必须拒绝引用不存在档案的启用网络规则，也必须拒绝重复 ID 或重复指纹。
   Provider 在 ACK 前执行同等校验，目录篡改会导致内容哈希不匹配。
6. format version 1 快照继续可读，并使用旧哈希算法；重建、系统规则升级或显式回滚
   会用当前数据库中仍受 revision/外键保护的配置档补齐旧快照没有保存的绑定，再生成
   version 2 新快照，不原地改写历史产物。引用已不存在档案时安全失败。
7. DNS 缓存分区标识和策略网络档案身份是两个概念。前者可以随路径、网卡、resolver
   和进程代数变化；后者只能由当前隐私指纹在已验证快照目录中唯一解析得到。

## 结果

- 网络规则拥有可跨进程、可回滚、可验真的身份来源，未来 macOS 和 Windows 共用
  同一快照契约。
- 原始 Wi-Fi 名称不会进入 SQLite、RPC 响应、策略快照、日志或诊断包。
- 仅建立目录和快照契约不等于运行时网络识别已完成；各平台仍须采集可用指纹、映射
  当前档案，并让 DNS 与透明代理 Provider 使用同一结果后，才能声明网络自动切换生效。
