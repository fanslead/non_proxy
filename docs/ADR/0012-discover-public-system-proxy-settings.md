# ADR-0012：只读发现系统公开代理设置

- 状态：已接受
- 日期：2026-07-31

## 背景

不少代理客户端会把本地 SOCKS 或 HTTP 监听地址写入 macOS 系统代理设置。普通用户
通常不知道协议、主机和端口，也不应被要求查看客户端日志或猜测请求地址。与此同时，
扫描任意本机端口、读取其他进程内存或猜测第三方客户端私有配置既不可靠，也扩大了
权限和隐私边界。

## 决策

1. macOS 宿主只通过 `SCDynamicStoreCopyProxies` 读取当前系统公开的 SOCKS、HTTP
   和 HTTPS 代理开关、主机与端口；不读取账号、密码、PAC 内容或代理排除列表。
2. SOCKS 候选按当前已实现的 SOCKS5 connector 检查；HTTP 与 HTTPS 目标代理设置
   映射为 HTTP CONNECT 候选。相同协议、主机和端口的项去重。
3. 原生桥接只返回固定协议类型、合法主机、1 到 65535 端口和产品生成的安全标识。
   ABI 升级到版本 6，Windows 和其他平台通过同一个 `ILocalProxyDiscovery` 接口接入，
   未实现的平台必须明确返回不可用。
4. 发现结果转换成现有 `proxy-uri-list-v1` 输入，并自动执行不写配置的预检。用户仍需
   明确保存；保存后的握手测试和签名公网出口验证继续使用既有流程。
5. 不扫描端口、不枚举任意监听进程、不修改系统代理、不自动保存，也不把“系统设置
   中存在代理”表述成“代理握手或公网路径已经可用”。

## 结果

- 使用系统代理的常见客户端可以在不理解端口和规则语法的情况下进入统一配置流程。
- 发现、格式预检、保存、握手测试和公网出口验证仍是不同证据等级，不制造假阳性。
- TUN-only、未写系统代理或使用专有协议的客户端不会被发现；它们仍需标准链接、手动
  本地端口、后续受审查适配器或隔离胶囊支持。
