# ADR-0042：已保存订阅可在不回显地址的情况下修改设置

## 状态

已接受。

## 背景

订阅 URL 常包含 Token，只能保存在系统凭据库，不得经过列表 RPC 返回桌面端。
但原有 `UpsertSubscriptionSource` 每次都要求重新提交 URL 并访问远程网络，导致用户只是
改名、停用或修改刷新间隔时，也必须再次寻找和粘贴秘密地址。这既不适合小白用户，也会
扩大秘密在剪贴板和托管字符串中的暴露面。

## 决策

1. 保持现有 RPC 和字段编号兼容。创建新订阅或更换地址时，`endpoint_url` 仍必须是
   非空 HTTPS URL；只修改已存在订阅的名称、启停或刷新间隔时，客户端发送空字节字段，
   表示继续使用权威状态中的凭据引用。
2. 空地址只在订阅源已存在且 `expected_revision` 与当前修订号一致时接受。新建请求
   返回 `NP_SUBSCRIPTION_ENDPOINT_REQUIRED`，并且不创建数据、不读取凭据、不访问网络。
3. 设置更新只通过 SQLite IMMEDIATE 事务和修订号 CAS 写入名称、启停、间隔、修订号与计划
   时间；凭据引用、内容代次、节点归属和出口保持不变。
4. 重新启用订阅时将下次刷新时间设为当前时间，让调度器尽快验证内容；已启用订阅缩短
   间隔时只会把计划时间提前，不会意外延后既定刷新。停用时保留原计划时间，但调度器
   不会选取停用源。
5. 成功结果使用 `content_unchanged = true`，明确表示本次操作未抓取或更换订阅内容。

## 后果

- 桌面端可以提供一键停用、重新启用和改名，不需要回显或重填 Token URL。
- 如果用户确实要更换 URL，仍走原有先拉取、准备、写凭据、原子提交与补偿清理链路。
- Protobuf `bytes` 没有 presence 信息，因此空值语义必须保持在契约注释、跨语言生成物和测试中。

## 验收边界

gatewayd 测试要求设置更新后修订号递增、内容代次不变、凭据引用和秘密值不变、远程
拉取器不被调用，并覆盖停用后重启的立即调度以及无 URL 创建被拒绝。这些证据不等于桌面
交互或真实 Keychain/Credential Manager 设备验收。
