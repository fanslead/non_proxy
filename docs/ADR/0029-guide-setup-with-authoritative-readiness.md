# ADR-0029：以权威就绪状态持续引导两种接入路径

- 状态：Accepted
- 日期：2026-07-31

## 背景

产品方案要求面向小白推荐完整网关或第三方客户端协同，但当前平台尚不能完整检测
MDM、Always-On VPN 和所有第三方 TUN。一次性首次启动向导如果把“用户点过下一步”保存为
完成，很容易在系统授权撤销、快照等待确认或 Adapter 宿主离线后继续显示已就绪。

完整网关和客户端协同的证据边界也不同：前者由 NonProxy 数据面产生路径记录；后者当前只
能确认候选、配置写入与客户端重载，登记成功不能推导为第三方 VPN 已被绕过。

## 决策

1. 运行概览提供常驻“选择接入方式”，不持久化向导完成标志。每次刷新都从系统组件、出口
   目录、活动快照、数据面状态和隔离 Adapter 登记目录重新计算。
2. 完整网关只有在系统组件已安装、默认路由引用现存代理、活动快照至少包含一条直连规则且
   活动数据面已确认时显示“基础链路已就绪”。草稿、待确认、待移除或拒绝规则不能满足该
   门禁。代理握手的 60 秒新鲜度仍是设置默认路由时的服务端
   门禁；过期的设置期握手不会被误报为正在运行的数据面故障。
3. 客户端协同在存在可用登记项时仍保持“待同步/待取证”。在真实路径证据可持久化并绑定到
   对应变更前，概览不得把 Adapter 路径显示为就绪。
4. gatewayd 或 adapter-host 的预期不可用分别降级对应路径卡片，不清空另一条路径和系统组件
   的权威状态。无效契约等非预期异常仍进入统一错误边界，不能静默吞掉。
5. 高频连接决策事件只重读运行概览，并用最近一次完整刷新得到的出口与 Adapter 目录重算
   文案；快照、系统状态、组件事件和用户刷新才重新读取两个接入目录，避免把每条流量事件
   放大为跨两个本地服务的全目录查询。
6. 引导按钮只通过共享 `IWorkspaceNavigator` 请求切换现有页面。导航器不复制业务状态，
   `MainWindowViewModel` 仍是当前页面的唯一所有者。
7. 自动检测 MDM、Always-On VPN 或任意第三方 TUN 在真实平台能力落地前不进入推荐算法；
   UI 明确提供两条路径，由用户选择，不宣称已经自动识别环境。

## 结果

- 首次使用、授权恢复和后续故障使用同一套可回归状态，不会出现过时的“向导已完成”。
- macOS 与 Windows 共享状态模型和导航；Windows 未具备系统组件或 Adapter 传输时继续显示
  明确不可用。
- “基础链路已就绪”只表示完整网关的配置与活动数据面门禁通过，最终 DIRECT/PROXY 结果仍
  必须在活动记录或签名出口回执中逐条核对。
- Headless UI 测试覆盖两平台组合和可访问名称；真实系统授权、正式签名与真实 VPN 共存仍
  属于平台验收。
