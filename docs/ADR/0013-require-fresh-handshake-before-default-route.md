# ADR-0013：默认代理必须通过当前配置的新鲜握手测试

- 状态：已接受
- 日期：2026-07-31

## 背景

协议类型和静态能力只能说明一个出口理论上可承载哪些流量，不能证明地址、端口、
凭据或本地代理进程当前可用。若仅由桌面端根据能力开放“设为默认”，其他控制客户端
仍可绕过界面，把一个从未连接成功或已经失效的代理写入 fail-closed 默认路由。

## 决策

1. `gatewayd` 是门禁的权威执行者。默认路由目标为代理时，必须在持有网络配置变更
   互斥锁期间校验 routing revision、出口存在性、启用状态和完整网关能力。
2. 同一个 `outbound_id` 和出口配置 revision 必须在最近 60 秒内拥有 `READY` 握手
   观察。失败、超时、进程重启、出口配置 revision 变化或观察过期都恢复为“未验证”。
3. 任一校验失败时返回稳定错误码 `NP_DEFAULT_OUTBOUND_UNVERIFIED` 或既有的具体
   revision/出口错误；不得修改 `routing_settings`，也不得创建 pending 快照。
4. 恢复默认直连不依赖代理健康，继续使用鉴权、乐观 revision、原子快照和 Provider
   ACK 流程。
5. 共享桌面端只对已启用、具备完整能力且握手已验证的非默认出口开放“设为默认”，
   并明确提示“需先通过握手测试”。服务端校验不能因客户端已禁用按钮而省略。
6. `READY` 控制契约必须同时带有检查时间和握手延迟；证据不完整时客户端拒绝目录，
   不把枚举值单独解释成成功。

## 结果

- 新用户无法因只保存了错误代理地址就把未命中流量切入不可用默认路径。
- UI、其他本地客户端和未来 Windows 宿主共享同一个不可绕过的服务端安全边界。
- 握手仍只证明固定目标的代理 TCP 协商成功，不代替 Provider ACK、规则命中、DNS、
  UDP、IPv4/IPv6 或签名公网出口证据。
- 历史快照回滚继续恢复其权威默认路由，不要求重新握手；回滚属于受控恢复操作，
  不是新的默认出口选择。
