# ADR-0011：先预检再导入标准代理链接

- 状态：已接受
- 日期：2026-07-31

## 背景

手动填写代理类型、主机、端口和凭据适合单个本地端口，但普通用户更常拿到一条或
多条代理链接。要求用户把链接拆成字段或编写内部 JSON，既容易出错，也会诱导用户
把带密码的配置复制到日志、截图或不受控文件中。

同时，NonProxy 当前只真正实现 SOCKS5 和明文 HTTP CONNECT connector。仅仅识别
更多 URI scheme 会制造“已经支持该 VPN 协议”的假象，因此导入范围必须和数据面
能力完全一致。

## 决策

1. 新增 `proxy-uri-list-v1` 导入格式，每行一个 URI，只接受 `socks5://`、
   `socks5h://` 和 `http://`。缺省端口分别为 1080 和 80。
2. 路径、查询参数、未知协议、无主机、零端口、畸形 UTF-8/百分号编码及不成对账号
   密码全部拒绝。错误只返回稳定错误码和行号，不回显原始 URI。
3. URI 片段作为可选名称，规范化为最多 128 字节的安全标识；缺少名称时根据协议、
   主机和端口生成，批内重复项追加确定性序号。
4. 桌面端采用“粘贴 → 检查 → 保存”两阶段流程。检查使用 `validate_only=true`，只
   展示标识、协议和端点；账号密码始终不出现在预览。源文本一旦变化，预览和保存
   权限立即失效。若生成的标识已存在，检查结果必须在保存前明确提示该出口将被安全
   更新。
5. 保存时 gatewayd 重新解析原文并读取最新 revision。全部新凭据先写系统凭据库，
   全部出口在一个数据库事务中提交；数据库失败则补偿删除新凭据，成功后清理旧引用。
6. C# 和 Rust 的临时 UTF-8 缓冲区在请求处理后归零。SQLite、RPC 响应、预览和日志
   都不保存用户名、密码或完整 URI。
7. 不接受 `https://` 代理，因为当前 HTTP CONNECT connector 不实现到代理服务器的
   TLS；也不接受 Shadowsocks、VMess、Trojan、WireGuard、OpenVPN 或订阅格式，直到
   对应数据面实现并通过独立安全审查。

## 结果

- 普通用户无需理解内部 JSON，也不会在保存前盲目导入一批配置。
- 预览内容与实际 connector 能力一致，不把“能解析字符串”冒充“能承载流量”。
- 带秘密的原始文本只跨越桌面进程到认证本地控制面，并沿用既有凭据隔离和补偿事务。
- 本能力是标准本地代理链接导入，不代表节点订阅、现代代理协议或 VPN 配置导入完成。
