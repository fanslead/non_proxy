# ADR-0027：第三方适配器只从活动策略快照投影规则

- 状态：已接受
- 日期：2026-07-31

## 背景

桌面策略目录同时描述草稿、待确认修订和正在执行的旧修订。当用户已经发布一个新修订、
但 Provider 尚未确认时，列表中的 `PolicyStatus.policy` 是新草稿，`effective_revision` 则仍
指向旧修订。第三方客户端若直接从列表生成规则，会提前应用尚未生效的内容，或者在删除
草稿处于 pending 时把仍由 NonProxy 数据面执行的旧规则移除。

## 决策

1. `ControlService.GetActivePolicySnapshot` 只读取 SQLite 中状态为 active 的不可变快照，
   解码其中的权威 policy payload，并返回快照版本、32 字节内容哈希和策略集合。
2. 没有活动快照时返回版本 0、空哈希和空集合。这是正常的“尚未生效”状态，不回退到
   当前草稿目录，也不猜测 pending 快照最终会被接受。
3. 响应中的策略来自构建快照时已排序、已校验的载荷。桌面端后续只负责把可表达的 DIRECT
   规则投影成 adapter `normalized-policy-v1`；应用路径等本机展示信息必须通过受信任的平台
   目录补全，不能从策略显示名推断。
4. `GetActivePolicySnapshot` 是只读本机接口，不改变快照状态。后续 adapter prepare/apply
   必须同时绑定返回的 `snapshot_version` 和 `content_hash`，并在写入前检查活动快照没有变化。
5. 配置已生成、客户端已重载和实际路径已验证仍是三个独立事实。本接口只提供策略来源
   一致性，不能提升 evidence level。

## 结果

- 待确认、被拒绝或待移除的草稿不会提前改变第三方客户端规则。
- adapter 同步拥有可审计的活动快照身份，并可在后续编排中检测同步期间的策略漂移。
- 增加了一个追加式只读 RPC 和对应生成代码；旧客户端不受影响。
- 真实客户端同步、失败回滚和路径证据仍由 adapter-host 与桌面编排分别完成。
