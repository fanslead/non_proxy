# ADR-0037：导入 Shadowsocks 订阅内容但不持久化订阅源

- 状态：已接受
- 日期：2026-08-01

## 背景

许多 Shadowsocks 服务把多条 `ss://` 节点链接包装成一段 Standard 或 URL-safe Base64。
要求普通用户自行解码后逐行粘贴，仍然暴露了不必要的配置知识；但直接接收订阅 URL 又会
同时引入 Token 存储、SSRF、重定向、DNS rebinding、刷新并发和节点删除语义。解析核心与
远程生命周期应分批交付和审查。

## 决策

1. 控制面新增显式格式 `shadowsocks-subscription-v1`，不改变既有
   `nonproxy-json-v1` 与 `proxy-uri-list-v1` 语义，也不修改 Protobuf 字段。
2. 输入与解码内容都受 256 KiB 上限，解码结果最多 100 个非空节点。接受 Standard、
   URL-safe、带或不带 padding 的 Base64，并允许复制过程产生的 ASCII 空白；只解码一层。
3. 解码结果复用经过审查的 `ss://` 解析器，且整批只能包含 Shadowsocks。任何 SOCKS5、
   HTTP、未知协议、非法方法、密钥或 URI 都使整批失败，不进行部分导入。
4. 预览仍使用 `validate_only`，只返回协议、规范化标识和服务器端点。保存继续使用同一套
   revision 检查、系统凭据库写入、SQLite 原子更新和失败补偿；输入及 Base64 解码字节缓冲区
   在使用后归零，不进入日志、错误消息或 RPC summary。
5. 共享桌面端把包含 `://` 的输入作为标准链接列表，其余输入作为订阅内容；该判断只选择
   RPC 格式，不能绕过 `gatewayd` 的大小、Base64、协议和凭据校验。用户修改源文本后预览
   立即失效，必须重新检查才能保存。
6. 本批不持久化订阅 URL，不发起网络请求，不保存刷新 Token，不实现定时刷新，也不声称
   对订阅中节点的重命名、删除或顺序变化进行生命周期管理。

## 后果

- 普通用户可以直接粘贴常见 Shadowsocks 订阅响应，无需自行解码或理解每个节点地址。
- 离线解析与秘密隔离成为后续远程订阅管理可复用的安全边界；远程获取仍必须单独完成
  HTTPS、解析后地址固定、私网阻断、重定向复检、响应上限和原子刷新设计。
- 重新导入相同标识会按现有 revision 语义更新出口；这不是完整的订阅归属或自动清理。

## 验收边界

仓库测试覆盖 Standard/URL-safe、padding、换行、非法 Base64、混合协议、预览不写入、
凭据库隔离、桌面格式选择和去敏错误。测试不证明任何供应商 URL 可访问、远程刷新安全、
节点健康、真实公网路径或正式签名系统扩展已经通过。
